# 公開前チェックリスト

所有者の確認と引き継ぎ用です。未記入の項目を実施・承認済みと扱わないでください。本番公開、DNS変更、新規外部サービスの契約・課金、秘密情報の設定は、所有者が具体的な内容を確認してから実施します。

## 1. 公開に必要な判断

- [ ] 公開先のGitHubリポジトリ・本番ブランチ・Cloudflareアカウントと管理責任者を決定する。
- [ ] 公式サイトを顧客向け共通アプリ・各店舗アプリから分離して管理する。
- [ ] 正式な公開URLと独自ドメインの必要性、取得費用、DNS変更の有無を確認する。
- [ ] 月額20,000円と初期費用0円の目標を提供予定として掲載してよいか確認する。税込・税抜、契約期間、解約・返金、提供範囲、追加費用は確定事項だけを表示する。
- [ ] 問い合わせの受付開始日、受信先、対応担当者、対応体制を決める。未確定の返信時間・納期は約束しない。
- [ ] メール送信サービス・Turnstile等の利用先、料金、データの取り扱いを確認し、契約・設定の要否を承認する。

## 2. 表示内容・法的表示

- [ ] 屋号は「oneight」。存在しない法人格・所在地・創業年・代表者経歴・実績・利用者の声を掲載していない。
- [ ] 機能は実際の開発・提供状態に合う表現になっており、未実装の機能を完成済み・標準搭載と誤認させない。
- [ ] モックアップに「画面イメージ」と表示し、架空の利用例を実績と誤認させない。
- [ ] 写真・フォント・アイコン・画像・ロゴに利用許諾上の問題がない。実在店舗の素材は許可を得ている。
- [ ] 売上・リピート率等の効果を保証せず、LINE等との比較が正確である。
- [ ] 個人情報を扱う事業者の正式な氏名・名称、連絡先、必要な所在地等の表示を確認する。
- [ ] プライバシーポリシーに取得項目、利用目的、保存・削除方針、窓口、委託先・外部サービス・国外での取り扱いの実態を反映する。
- [ ] フォームの同意文とポリシーのリンクが一致し、送信前に読める。
- [ ] オンラインでの契約・決済の有無を確認し、必要に応じて特定商取引法等の表示、利用規約、個別契約書、解約条件を整備する。問い合わせだけで契約が成立するかどうかも整理する。
- [ ] 公開前確認中の文言・不足情報を解消する。判断できない法的事項は適切な専門家へ確認する。

## 3. 環境・送信設定

- [ ] Node.js 24で `npm ci` が成功する。
- [ ] `PUBLIC_SITE_URL` に決定したHTTPS originを設定する。仮ドメイン、パス、クエリ、認証情報を入れない。
- [ ] Previewでは `PUBLIC_ALLOW_INDEXING=false` とし、本番の検索登録は承認後のみ `true` にする。
- [ ] 検索登録前にcanonical・OGP・sitemapが同じ正式URLを指すことを確認する。
- [ ] [お問い合わせの設定](contact-setup.md) を完了し、Pages Functionsに必要な設定値がそろっている。
- [ ] 送信APIキー・Turnstile secret keyはサーバー側の秘密情報に設定する。`PUBLIC_` 変数やGitへ入れない。
- [ ] 送信有効化前に、本番ホストでTurnstileが動き、所有者の受信先へメールが届くことを確認する。
- [ ] 無効時は受付準備中と表示し、送信できたように見せていない。
- [ ] 入力エラー・同意なし・スパム検証失敗・外部API障害時の表示を確認する。
- [ ] `.env`・`.dev.vars`・秘密情報がGitの追跡対象になっていない。

## 4. 品質確認

- [ ] `npm run verify` が成功する。実行日時・結果は作業記録に残す。
- [ ] デスクトップとスマートフォン幅で全ページの横はみ出し、文字、モックアップ、ナビゲーション、料金、CTAを確認する。
- [ ] キーボードで操作でき、フォーカス位置がわかる。
- [ ] フォームの必須項目、ラベル、エラー表示、送信状態を確認する。
- [ ] 動きを減らす設定で閲覧でき、過度なアニメーションがない。
- [ ] リンク・画像・404・戻る導線が動く。ページ固有のtitle・description・h1を確認する。
- [ ] 本番で `robots.txt`・`sitemap.xml`・favicon・OG画像にアクセスできる。404は404ステータスで返る。
- [ ] パフォーマンス・画像サイズ・表示の安定性を確認する。Lighthouse等の点数は実測した場合だけ報告する。

## 5. 承認後の公開・運用

- [ ] 公開する変更、公開先、検索登録、フォーム受付、外部サービス、費用を所有者が確認し、本番公開を承認する。
- [ ] Pagesの初回デプロイやGit連携開始が公開を伴うことを確認する。
- [ ] 承認された設定でデプロイし、公開URLで全ページとメール到達を最終確認する。
- [ ] DNS変更が必要なら、対象レコードと影響を提示して承認後に実施する。
- [ ] 更新担当、秘密情報の保管・更新方法、受信対応、障害連絡先、ロールバック方法を記録する。
- [ ] 問い合わせの保持期限と削除担当、外部サービスの課金・利用状況の確認方法を決める。

実績・お知らせ・実際のデモ・アクセス計測は、初回公開後に必要性と管理負担を確認して検討します。計測ツール追加時は、同意やプライバシーポリシーの更新要否も確認してください。
